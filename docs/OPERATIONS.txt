更新日期：2026-10-27
适用范围：原发布包、当日线上图库快照、新版界面及原桌宠兼容层。

1. 直接打开与本地预览

完整解压后，直接用现代浏览器打开根目录index.html即可。新版使用相对资源链接、普通脚本与按需脚本加载，可从file://打开；无需构建、npm install、付费服务或CDN。
保留入口HTML与memorial/、assets/、backgrounds/、gallery-examples/、daily/的相对位置。原站远程图库、原视频、作者主页与桌宠精灵图仍需联网。
本地file://的存储与下载权限由浏览器决定；需要稳定的同源记录时，使用以下Node预览。

Node.js 20或更新版本，无第三方依赖。在项目根目录运行：

  npm run dev -- --host 127.0.0.1 --port 5173

打开 http://127.0.0.1:5173/。保持协议、主机和端口不变，才能继续读取同一来源的localStorage。
npm start与npm run dev等效。legacy/里的旧HTML仅为完整性存档，原根路径引用不保证可直接从file://独立运行。

2. 构建与部署

  npm run build
  npm run preview -- --host 127.0.0.1 --port 4173

第二条命令预览dist/。build只按scripts/site-files.mjs复制公开文件，每次重建dist/；它不恢复原React/TypeScript源码、不压缩原图、不自动上传。
部署只上传dist/，不要直接公开整个仓库。docs/、legacy/、scripts/和qa-页面不进入公开产物。
legacy/daily/index.html与legacy/review.html包含原始未折叠内容，直接公开会绕过新版门控；新版同名入口已保留并接续内容。
新增公开目录需同步scripts/site-files.mjs。新版本地资源采用相对路径，子路径托管时仍要测试根页、daily/页面、图片、脚本和分享图片。
原_headers、_routes.json、_worker.js按原路径保留。只有支持相应规则的托管平台会执行；纯静态托管不会自动建立图库后端。
本地命令不更改域名、仓库可见性或访问受众。实际部署状态以完成的部署结果为准。

3. 原素材与内容保全

原71文件/19,236,169字节为导入基线：63个非HTML仍在原路径，8个原HTML字节完整保存在legacy/对应路径；原公共入口由新版接续。
42个原媒体文件记录于memorial/material-data.js，archive.html经剧情确认后提供全部原文件入口。包含原先7个未在主页面引用的封面/重复版本、全部24个响应式候选和原装饰。24个响应式图同时用于首页srcset，浏览器按需选择，避免全部预加载。
49条视频、原作者、原帖与data URI封面在original-data.js；87图/67组的原线上元数据在gallery-data.js；176候选审核原页在review-data.js；246条原字面文案可在建站足迹查看。
246条是字面字符串提取，不自动证明所有模板/拼接文案已逐句核对。旧HTML与旧bundle保留为原件，不删除重复构建文件来减小体积。
详细路径映射见MATERIAL-MAP.txt，逐文件校验见ASSET-AUDIT.txt。

离线核对命令：

  npm run verify:preservation
  node scripts/verify-preservation.mjs --json
  node scripts/verify-preservation.mjs --root /absolute/path/to/project --json

脚本只读本地文件，不访问网络、不执行数据脚本。它检查71项基线的大小/SHA-256/Git blob SHA、8份归档HTML、49视频关键字段与原data URI、87图/67组原元数据和组成员。
退出码0表示这些离线检查通过，1表示保全差异，2表示参数错误。它不测试远程图像字节、作者真实性、视觉布局、浏览器下载和全部交互。
检查对象应为完整项目或完整源包，不是故意排除docs/legacy/的dist/。
发现差异应从原导入包或受信任Git基线恢复；不要改写import-manifest.json掩盖差异。新增内容另记来源和审校信息。

4. 图库和后端依赖

原图库来源：https://preview.daniya.cc/gallery
原媒体记录保留/api/gallery/archive/<原ID>及其/thumb路径，来源域为https://preview.daniya.cc。
新版解析器将原图库API指向原域，本地示例仍指向当前file://或HTTP资源；file/data/blob地址不会拼接到远程域。
docs/live-gallery-snapshot-20261027.json不含87张远程原图的二进制备份。离线/原域停机/访问策略改变时，线上图库可能不可见，应保留失败状态与原链接。
如要迁移自有归档服务，站长需提供真实GALLERY_ARCHIVE_ORIGIN、数据和媒体备份。该环境变量是既有归档服务的HTTPS根地址，不能凭猜测设为预览域。
原_worker.js为只读代理；本地serve.mjs支持该变量，未设置时相关代理API返回503。当前新版可继续使用原站已取得的真实媒体地址，不假装已建新数据库。

5. 署名、资料与剧情维护

49条视频保留原作者及主页/原帖。67组画廊与3个本地分类示例的原作者、主页、原帖在原数据中缺失，显示待补录；组名像账号也不能直接当署名。
补署名时保留原历史字段，并同步卡片/灯箱/致谢。原站归档图像链接不能标为“原作者原帖”。下架入口为项目GitHub Issues，私密邮箱保留明确占位。
主代理已目检87个成员缩略图与原可见标题；43组可公开，24组不确定或剧情相关组封存。高清细字未逐字转写；新增或替换图片应重新审校，并更新review字段。
视频30条经审元信息可公开、19条元信息封存；所有简介/标签默认封存。外链视频未逐帧审查，未解锁访问前提示，再由访客点击继续原帖。
剧情、原文存档、历史媒体、审核工具使用同一确认，选择只存当前session；重新封存应清理已展开DOM/iframe和详情。首页、页面元信息、Open Graph与留声卡使用安全内容。
角色事实以profile-data.js记录的官方来源与核验状态为准；原创寄语明确标注。5月21日是沿用原站的相遇/等待起点，不擅自写成角色生日。

6. 桌宠兼容策略

课间时光优先尝试原站 https://preview.daniya.cc/pet/companion.js。
原脚本跨域加载或挂载失败时，自动载入本地memorial/pet.js，以同一原站精灵图 https://preview.daniya.cc/pet/denia.webp 运行兼容桌宠，不替换为新绘制人物。
九种动作按原站控件的精灵行/帧数/时长实现：待机、向右跑、向左跑、挥手、泡泡跳跃、低落、等待、原地跑、思考。
主代理在浏览器观察到正确角色、动作下拉及减少动效后的暂停；页面不可见和减少动效状态会暂停动画。精灵图仍是远程依赖，不宣称已打入离线包。
聊天、选图、表情包与朗读继续指向 https://preview.daniya.cc/pet-preview.html。原聊天目前的离线状态没有由新前端伪装恢复；本地兼容层只处理人物显示/动作/交互界面，不冒充原聊天后端。
兼容桌宠偏好键为denia.memorial.pet.v1。隐藏桌宠不会删除原站资源或聊天记录。

7. 心愿、收藏、审核记录与PNG留声卡

心愿仅保存在当前设备/当前来源域，不是公共留言，不自动上传或跨设备同步。
心愿键：denia.memorial.wishes.v1；每条1–280字，最多200条。导入校验格式/长度/时间/数量，合并去重，格式错误不覆盖已有记录。
备份有四个入口：下载JSON、从文件导入、复制备份文本、粘贴备份文本。下载被浏览器阻止时，可复制完整JSON到自己的文本文件；在新来源粘贴同一JSON后导入。复制权限不足时显示可手动选择的文本框。
本地存储不可用或已满时，界面说明当前仅临时保存；关闭前使用上述备份。导出内容含填写的名字与心愿，按个人意愿保存或分享。

新版视频收藏键：denia-memorial-video-favorites:v1；画廊收藏键：denia.memorial.gallery.favorites.v1。不会清空旧站未知键。浏览器记录不随Git/ZIP迁移。
原176条审核页的脚本、键名、备注与JSON导入导出保留，明确展开后用同源srcdoc载入。换协议/域名/端口或改用file://前，应在原来源导出审核和心愿备份，再在新来源导入。
不要改为跨域iframe或不允许同源的沙箱后，仍声称旧审核记录能自动读取。

PNG留声卡先显示预览对话框。访客可点击下载，也可在预览中长按/右键保存；同时保留台词与出处文字复制。PNG生成失败时回退到完整文字和出处，不伪造下载成功。
图片下载由浏览器处理，前端发起保存不等于能读取用户磁盘确认保存。请在下载列表或预览另存后自行确认文件。
